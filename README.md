# nufe-network-assistant · 南财校园网助手

**减少认证过期带来的断网与远程失联，让校园网认证和账号数据查询一站完成。**

面向南京财经大学校园网的 Windows 客户端，将本机校园网认证、后台保活、网络状态查看、设备管理和账号数据查询集中在一个工具中。

[MIT 许可证](LICENSE) · [架构说明](docs/architecture.md) · [开发指南](docs/development.md) · [参与贡献](CONTRIBUTING.md)

## 为什么做这个工具？

最初的需求来自远程使用电脑：**人不在设备旁边，却需要通过远程控制工具连接电脑。** 如果此时校园网认证过期，设备即使仍连接着 Wi-Fi，也可能无法访问互联网，远程控制随之失联，而人又无法到场重新认证。

另一个常见场景发生在日常使用中：电脑突然无法访问互联网，排查后才发现是校园网认证过期。网络已连接和认证仍有效并不是一回事，缺少直观的状态信息，就容易花时间寻找原因。

这个工具因此从认证与保活出发：在启用后自动检查、尝试恢复认证，同时把认证状态和外网状态分别展示出来。再将设备、上网记录、账单和业务信息等自助功能整合进来，形成校园网的一站式管理入口。

## 它能帮你做什么？

| 使用场景 | 对应能力 |
|---|---|
| 设备无人值守，需要通过远程控制工具连接 | 后台按设置检查认证状态，在符合条件时尝试重新认证，减少因认证过期导致的远程失联 |
| 使用电脑时无法上网，希望尽快定位认证是否失效 | 直接查看认证状态与当前认证账号，并结合独立外网探测、网络名和实时网速判断情况 |
| 希望在同一个地方完成联网和账号管理 | 集中进行本机认证，查询在线设备、绑定设备、上网记录、账单及业务信息，办理受支持的自助操作 |
| 多台设备共用账号，在线设备数达到限制 | 用白名单明确需要保留的设备；启用自动超限处理后，按规则从其他设备中选择候选，尝试释放名额 |

## 核心优势

### 面向无人值守的认证保活

启用保活后，工具按所选策略检查本机校园网认证，在允许的条件下自动尝试重新认证，减少人不在设备旁时需要到场登录的情况。关闭前台窗口后，已启用的保活仍可继续。

这让需要远程连接电脑的人，多了一层针对校园网认证过期的恢复机制；日常使用时，也能减少反复打开认证网页的操作。


### 看清状态，再决定是否恢复

校园认证在线、外网能否访问、保活有没有启用，是三个不同的问题，工具分别判断和展示：

- **认证在线、外网异常**：保留当前连接，不自动下线重登。
- **离开校园网络**：只在确认 `NUFE-STU` 后执行校园认证，其他网络不尝试自动登录。
- **密码被拒绝**：停止自动提交，等待修复；已有其他账号在线时，不自动顶替。

### 认证与账号数据查询，一站式管理

从查看本机网络到查询校园网账号数据，无须将认证工具与自助查询割裂使用。五组导航覆盖网络概览、我的设备、用量与记录、业务管理和设置，支持：

- 查看在线设备、绑定设备，手动管理设备连接。
- 查询上网记录、账号账单和业务记录，导出受支持的记录。
- 管理运营商绑定，办理受支持的报停与复通操作。

手动设备下线、解绑、运营商及业务变更等操作先刷新并预览，再进行限时单次确认；结果不确定时不自动重复提交。本机报停后即使复通，也不会擅自恢复保活。

### 设备白名单，优先保护常用设备

多设备使用时，重要的是明确**哪些设备需要保留**。你可以从在线设备或绑定设备中，将常用手机、电脑等加入当前账号的保留白名单。

白名单与自动超限处理配合使用：

- **保留常用设备**：白名单内设备不会成为本工具自动下线的候选，本机也会额外受到保护。
- **按规则释放名额**：明确启用并授权后，遇到认证设备数超限时，工具可按配置的上线时间顺序，从非白名单且非本机设备中选择候选，尝试释放名额并恢复认证。
- **处理有节制**：每轮最多处理一台；没有合适候选、无法确认状态或处理失败时，停止本次处理。
- **规则随账号保存**：各账号分别维护白名单，切换账号时载入对应规则。

例如，可以将仍需联网的手机和另一台电脑加入白名单；设备数超限时，让工具按已配置规则处理其他候选，减少每次重新辨认要保留设备的操作。

白名单是本工具的设备保留规则，不改变学校的在线设备数量限制。加入白名单不会自行开启自动处理，是否自动下线其他设备仍由你单独决定。

### 两种保活方式，兼顾响应与常驻负担

| 方式 | 适合的使用习惯 | 运行方式 |
|---|---|---|
| 常驻后台程序 | 希望网络变化或正常唤醒后也能及时检查 | 独立 Agent 常驻，可选登录 Windows 后启动；关闭前台仍可保活 |
| Windows 任务计划程序 | 接受周期检查，希望减少应用进程常驻 | 当前用户登录期间定期启动子工具，执行后退出，不弹控制台窗口 |

两种方式互斥，切换时替换原策略。任务模式无常驻托盘提醒，网络变化等待下一轮；两种方式都不会主动唤醒睡眠中的电脑。

可在“设置 → 运行偏好 → 保活与启动”填写**计划任务名称**（例如“南财校园网助手”），点击“应用计划名称”单独保存。已有任务改名时保留原有间隔、启用及暂停状态，移除旧名称，不覆盖已被占用的名称；尚未注册任务时只保存名称，不自动开启保活。两种策略共用此名称，任务位于 Windows **任务计划程序库根目录**，列表未更新时按 F5 刷新。名称留空沿用旧版的 `NufeCampus-<Windows 用户 SID>`，自定义名称只保存在本机，不随偏好备份导出。

原生 WPF 前台与 NativeAOT 后台分开运行，HTML 解析等自助处理按需执行；最小化暂停前台采样、绘图和轮询，减少无须展示时的工作量。实际资源占用随设备、网络和使用场景变化，不承诺固定内存或 CPU 数值。

### 信息持续更新，刷新频率由你决定

打开前台即可独立获取认证状态和当前认证账号，不需要先启用保活或保存密码。网络名及上传、下载速率每秒更新，无须主动测速。外网探测也支持其他 Wi-Fi、手机热点、有线及 VPN 网络，默认沿正常网络路径（含系统代理设置）执行；手动选择“校园网源地址绑定”时才限于校园网。探测结果表示检测服务是否可达，不代表所有网站和应用均可访问。

“设置 → 运行偏好”可分别配置：

| 项目 | 默认间隔 | 可配置范围 |
|---|---:|---:|
| 前台认证查询 | 3 秒 | 1–3600 秒 |
| 前台外网探测 | 120 秒 | 5–86400 秒 |
| 常驻后台保活 | 30 秒 | 10–86400 秒 |
| 任务计划保活 | 初次切换为 60 秒 | 60–86400 秒，须为整分钟 |

前台两项独立计时，认证查询调慢不会拖慢外网探测，也可无需账号单独应用。最小化暂停，恢复、切网或手动刷新可提前检查；请求耗时和系统调度会影响实际完成时间。

### 每次保活做了什么，直接查看记录

前台侧栏的“保活记录”按次展示常驻后台和计划任务的执行时间、检查情况、处理结果及耗时，选中一条即可查看有序的执行过程。例如：已经认证时记录“已在线，无需认证”；离线时记录认证尝试及成功、失败或结果未确认；离校、暂停、缺少凭据或执行入口被占用时记录跳过原因。前台实时状态查询不会生成保活记录。

记录从支持此功能的版本开始积累，保留最近 7 天且总量最多 5 MB，界面展示最近 300 次；打开记录页时每 5 秒刷新，最小化暂停。只保存时间和固定操作/结果码，不保存账号、密码、IP、MAC 或服务器原文。

### 保存账号和自动运行，分别由你选择

首次使用主动引导填写账号、密码和运营商，默认“仅本次使用”。

- **仅本次使用**：密码只保留在窗口内存，关闭后失效，可手动认证和登录自助。
- **加密保存**：使用当前 Windows 用户的 DPAPI，不提供明文回退，密码不回填到界面。
- **启用保活**：需要加密保存凭据，再单独开启保活并确认校方 HTTP 传输说明；保存账号本身不会开启保活。

自助会话保留在内存。日志只记录时间和固定事件码，不记录密码、Cookie 或平台原始响应。

### 关闭、退出和卸载，各有明确行为

- **关闭窗口**：只结束前台，已启用的保活继续。
- **注销本机认证**：仅注销当前配置账号在本机的校园网认证，操作前确认并核对当前账号；不暂停或关闭保活，已启用时可能很快自动重新认证。已离线时不重复注销，结果不确定时不自动重发。
- **退出程序及后台**：常驻模式结束本次后台；任务模式停止并移除周期任务，避免下一轮又启动。两者都不注销校园连接。
- **安装与卸载**：当前用户安装，无须管理员权限，自带 .NET 运行时、开始菜单入口和卸载程序。

常驻模式退出不改变下次登录自启动偏好；任务模式停止后需手动启动保活或保存应用来恢复。安装与升级不会自动运行保活任务。

## 快速开始

### 获取与设置

普通用户可直接[下载 Windows x64 安装包（v1.1.0）](https://github.com/Halcyonjoy/nufe-network-assistant/releases/download/v1.1.0/NUFE-Campus-Setup-1.1.0-x64.exe)，对应的 [SHA256 校验文件](https://github.com/Halcyonjoy/nufe-network-assistant/releases/download/v1.1.0/NUFE-Campus-Setup-1.1.0-x64.exe.sha256)可用于核对下载内容。

新版本及安装说明见[最新 Release](https://github.com/Halcyonjoy/nufe-network-assistant/releases/latest)。Release 页面中的 `Source code` 是源码，不是安装程序；需要自行构建时请参考[开发指南](docs/development.md)。

### 下载与运行时的安全提示

当前发布的 v1.1.0 安装包未进行代码签名。浏览器或 Windows 可能提示“下载不常见”“未知发布者”或要求进一步确认；新程序尚未建立下载信誉也可能触发此类提示。相关机制见[微软说明](https://learn.microsoft.com/windows/apps/package-and-deploy/smartscreen-reputation)和 [Chrome 说明](https://support.google.com/chrome/answer/6261569?hl=zh-Hans)。

请从本仓库的 Release 页面下载，并将安装包的 SHA256 与对应校验文件核对，确认文件一致。信誉提示本身不等同于已检出病毒，校验值一致也不代表安全检测结论；如果出现具体恶意软件名称、文件被隔离或校验不一致，请暂停安装并通过 [Issues](https://github.com/Halcyonjoy/nufe-network-assistant/issues)反馈完整提示。无需关闭浏览器或系统安全防护。

### 安装与首次使用

安装版运行 `NUFE-Campus-Setup-<版本>-x64.exe`；免安装版从完整发布目录运行 `NufeCampus.App.exe`，保留配套文件。请使用普通 Windows 用户运行。

1. 填写学号、校园网密码，选择运营商。
2. 选择仅本次使用或本机加密保存；认证前确认校方入口传输说明。
3. 需要自动恢复时，再选择保活策略、设置间隔并启用。只想查看状态时，可以稍后设置账号。

### 命令行

在完整发布目录中，仅支持以下两个单参数命令：

```powershell
.\NufeCampus.Cli.exe --status        # 实时只读查询认证状态
.\NufeCampus.Cli.exe --authenticate  # 使用已加密保存的账号认证一次
```

查询不提交认证；认证一次不启用保活、不解除暂停或凭据拒绝保护。账号密码不通过命令行传入。输出为 JSON；退出码：0 成功、1 失败或保护拦截、2 参数或身份不支持、3 离校、4 运行锁占用、5 超时。

### 卸载

通过 Windows“设置 → 应用”或开始菜单卸载。默认保留本机账号、偏好、白名单和日志；需要清除时，先在工具“设置 → 运行偏好”执行“移除自启动与本机数据”，再卸载。

## 如何与学校服务器交互？

工具通过网络请求直接访问校方现有的校园网认证入口和自助服务平台，使用用户本人有权使用的账号完成认证、查询和管理。它把这些账号操作整合为本地客户端，并增加状态展示与定时检查。

| 认证与账号业务 | 访问的校方服务 |
|---|---|
| 查询本机认证状态、提交认证 | `http://10.200.253.5` 下的认证接口 |
| 查询设备、记录、账单及办理受支持的业务 | `http://10.100.0.3:8080/Self/` 自助服务平台 |

- **遵循服务端校验**：正常提交账号凭据和所需表单，服务器仍负责验证身份、权限和业务结果；不破解密码、不绕过验证码或访问控制。
- **操作限于账号权限内**：设备管理针对当前登录账号可管理的设备，不获取其他用户的账号数据。
- **不突破接入限制**：白名单决定本工具自动处理时保留哪些设备，不修改或规避校方、运营商的在线设备数量限制。
- **凭据直接用于校方业务**：认证与自助请求直接发往对应校方服务，不经项目自建的中转服务器。外网探测和主动测速会另行访问检测服务，不向其发送校园账号密码。

项目用于正常的校园网接入和账号自助管理，使用时应遵守适用法律、校方及运营商的使用规定。校方的[学生无线网络使用指南](https://ic.nufe.edu.cn/info/1182/1654.htm)介绍了认证入口、账号绑定及设备自助操作，可作为使用参考。

## 使用范围与边界

认证功能针对南京财经大学校园网 `NUFE-STU`。其他 Wi-Fi、手机热点、有线及 VPN 网络也支持网络名、实时速率展示和默认网络路径的外网探测，不代表支持其认证协议；不会修改系统代理、VPN、路由或 Windows 隐私权限。

目标平台为 **Windows 10/11 x64**。Windows 10、其他设备、睡眠恢复及长期资源表现仍需进一步实机验证。南京移动已有此前真实验证，镇江移动、南京电信尚未完成真实账号写入及认证验收；学校接口变化可能影响功能。

校方认证及自助入口使用 **HTTP**，本机 DPAPI 加密不能保护密码在校方网络中的传输。用户数据位于 `%LOCALAPPDATA%\NufeCampus`；偏好备份不含账号库、白名单、密码、同意状态和会话，不能代替完整换机备份。提交问题时请勿附真实凭据、个人表格或未脱敏记录，详见[安全说明](SECURITY.md)。

## 开发与贡献

源码采用 C#/.NET，业务策略、Windows 适配和自助平台分层组织。

```powershell
dotnet build NufeCampus.slnx -c Release
.\build.ps1
```

开发需要 .NET SDK 10.0.403 或同功能带兼容补丁版；NativeAOT 发布另需 Windows C++ 工具链与 Windows SDK，安装包使用 Inno Setup 7。详细步骤和检查方式见[开发指南](docs/development.md)。

| 目录 | 内容 |
|---|---|
| `src/` | 前台、后台、命令行、协议、存储、自助及安装维护源码 |
| `checks/` | 策略、协议、存储与 Windows 边界检查 |
| `assets/` | 可编辑 SVG 图标及 PNG/ICO |
| `installer/`、`tools/` | 安装定义、构建辅助和公开源码导出检查 |
| `docs/` | 架构、开发及发布说明 |
| `licenses/`、`.github/` | 第三方许可、CI 与问题模板 |

欢迎按[贡献指南](CONTRIBUTING.md)提交问题与改进。发布前按[发布说明](docs/release.md)检查源码；本地历史、验收证据、用户数据和编译产物不进入公开包。离线检查通过不等于真实校园网或跨设备验收已完成。
